# Модуль «Продукты и тарифы» (backend-economics)

Страница управления **экономикой** внешних бэков из CRM: каталог продуктов
(`product_id`, название, цена, период, **токены**) и тарифы списания за генерацию
(чат/фото/видео, **токенов за генерацию**) — с правкой количества токенов прямо в
ячейке таблицы. Плюс себестоимость и списание в истории запросов пользователя на
странице «Юзеры бэков». Решение — [ADR-072](../../adr/ADR-072-crm-admin-api-v11-economics.md),
API — [04-api.md#backend-economics](../../04-api.md#backend-economics),
UI — [08-design-system.md](../../08-design-system.md#страница-продукты-и-тарифы-нормативно-adr-072).

## Принцип

CRM — **прокси без собственного хранилища** ([ADR-069](../../adr/ADR-069-backend-users-page-admin-contract.md) §3
**подтверждён**, не отменён, [ADR-072](../../adr/ADR-072-crm-admin-api-v11-economics.md) §3):
продукты, тарифы и себестоимость **не копируются** в БД CRM — читаются на лету и
пишутся напрямую в бэк. Собственных таблиц и миграций модуль не добавляет.
Причина та же, что у [backend-users](../backend-users/README.md), и здесь она сильнее:
продукт и тариф — **денежные величины**, у которых недопустимо два дома.

Условия подключения бэка — те же три, что у [backend-users](../backend-users/README.md#принцип)
(реестр «Бэки» + health-check; **Admin API Key** в карточке бэка, Fernet, уходит
заголовком `X-Admin-Key`; контракт под одним из двух префиксов), **плюс четвёртое**:
бэк реализует **расширение v1.1 «экономика»** (таблица ниже). Бэк уровня v1
подключается и работает — модуль показывает информационное состояние
«расширение не поддерживается» (см. [Деградация](#деградация-нормативно)).

## Дельта контракта v1.1 «экономика» (только НОВОЕ относительно v1)

**Базовый контракт v1 — [modules/backend-users](../backend-users/README.md#crm-admin-api-contract-v1-сводка);
здесь он не дублируется.** Ниже — исключительно расширение. Имена путей и полей
**заморожены** ([ADR-072](../../adr/ADR-072-crm-admin-api-v11-economics.md) §1): обе стороны
реализуются разными командами в разных репозиториях, и расхождение в имени поля
даёт молча пустой экран, а не ошибку.

| Эндпоинт бэка (относительно префикса) | Статус | Что нового |
| --- | --- | --- |
| `GET /products?scope=grantable\|all` | **расширен** | элемент += **`tokens`** (int), **`avatar_tokens`** (int\|null), **`grantable`** (bool), **`updated_at`** (ISO\|null). Параметр **`scope`**, по умолчанию **`grantable`** — сохраняет сегодняшнее поведение формы «Установить план»; страница «Продукты и тарифы» зовёт **`scope=all`** |
| `PATCH /products/{product_id}` | **новый** | тело `{tokens: int≥0, avatar_tokens: int≥0?, if_updated_at: ISO?}` (хотя бы одно значимое поле); ответ = элемент продукта + **`previous_tokens`** + **`changed`** + **`effective_after_seconds`** |
| `GET /pricing` | **новый** | `{items:[…]}`; элемент: **`tariff_id`** (str, **opaque** — ключ пути `PATCH`), **`kind`** ∈ `chat\|photo\|video\|other`, `name` (str\|null), **`tokens`** (number), `updated_at` (ISO\|null) |
| `PATCH /pricing/{tariff_id}` | **новый** | тело `{tokens: number≥0, if_updated_at: ISO?}`; ответ = элемент тарифа + `previous_tokens` + `changed` + `effective_after_seconds` |
| `GET /capabilities` | **новый, опциональный** | `{contract_version, features[], limits{}, cache_effective_after_seconds}`; `features` ∈ `products.read`, `products.write_tokens`, `pricing.read`, `pricing.write_tokens`, `requests.costs`. **`limits` — замороженный состав:** `product_tokens_max` (int), `product_avatar_tokens_max` (int), `tariff_tokens_max` (number), `tariff_decimal_places` (int). **404 = «расширений нет»** |
| `GET /users/{id}/requests` | **расширен** | элемент += **`tokens_spent`** (number\|null), **`provider_cost_usd`** (number\|null), **`refunded`** (bool — **это тип КОНТРАКТА бэка v1.1**; в схеме **ответа CRM** он **`bool \| null`**, см. примечание под таблицей) |

> ⚠️ **Таблица выше описывает контракт БЭКА, а не схему ответа CRM — типы двух уровней различаются.** Реализовывать схемы CRM по этой таблице **нельзя**: единственный нормативный источник схем ответа CRM — [04-api.md#backend-economics](../../04-api.md#backend-economics) и [#backend-users](../../04-api.md#backend-users). Ключевое расхождение: **`refunded` — `bool` в контракте бэка v1.1, но `bool | null` в ответе CRM** (бэк уровня v1 поля не отдаёт, CRM нормализует отсутствие в `null`; **`null` ≠ `false`** — «не отдано» не равно «возврата не было»). Так же и поля `products`: `tokens`/`avatar_tokens`/`grantable`/`updated_at` в ответе CRM **nullable** — см. [§1.1](../../adr/ADR-072-crm-admin-api-v11-economics.md).

**Инварианты расширения** (полный список и обоснования —
[ADR-072](../../adr/ADR-072-crm-admin-api-v11-economics.md) §1):

1. **`provider_cost_usd = null` = «не измерено», НЕ ноль.** UI рендерит `—`, никогда
   `$0.00`; `value || 0`/`?? 0`/`coalesce` на уровне строки **запрещены**. Измеренный
   `0` рендерится `$0.00` — отличимо. То же для `tokens_spent`.
2. **`refunded: true`** — списание возвращено, при этом `tokens_spent` **остаётся
   заполненным** (возврат не обнуляет стоимость).
3. **404 на расширенном пути = исключительно «эндпоинт не реализован»**; неизвестный
   `product_id`/`tariff_id` на реализованном эндпоинте → **`400`** с `detail`.
4. **`GET /products` обязан работать и без расширения** — это probe-путь детекции
   префикса. **Следствие (норма, не догадка исполнителя,
   [ADR-072](../../adr/ADR-072-crm-admin-api-v11-economics.md) §1.1):** на v1-бэке этот
   путь отвечает **`200`**, поэтому поля v1.1 в схеме CRM **nullable**, отсутствующее
   поле нормализуется в `null` (`502` из-за него **никогда**), `tokens: null` ⇒ `—` +
   read-only строка, `grantable: null` ⇒ `—` (а не «Нет»), а «`items` непуст и ни один
   элемент без `tokens`» ⇒ таблица «Продукты» переходит в тот же информационный блок,
   что и «Тарифы». **Асимметрия намеренная:** `/pricing` существует только в v1.1 ⇒ его
   поля **обязательны**, их отсутствие = `502 backend_admin_unavailable`.
5. **`PATCH` идемпотентен** (устанавливает значение, не дельту): ключ идемпотентности
   не нужен, повтор с тем же значением → `changed: false`.
6. **Право записи выводится ТОЛЬКО из `features`**, не из наличия поля `tokens`
   (бэк вправе отдавать токены read-only). **`capabilities: null` = «фич НЕ
   подтверждено»**, а не только «эндпоинта нет»: `404`, таймаут, `5xx`, `401`/`403`,
   битый JSON — любой неуспех подзапроса даёт `null`, **список при этом отдаётся**
   ([ADR-072](../../adr/ADR-072-crm-admin-api-v11-economics.md) §7.1). **Отсутствующий
   ключ `limits` ⇒ клиентская проверка по нему НЕ выполняется**; `limits`/`capabilities`
   нет вовсе ⇒ проверки границ нет, форма работоспособна; **незнакомый ключ игнорируется**.
   ⚠️ **У `limits` собственного номера инварианта в контракте НЕТ** — дом нормы —
   [ADR-072](../../adr/ADR-072-crm-admin-api-v11-economics.md) **§7.2**; ссылаться на
   «соседний» инвариант вместо §7.2 не следует. Там же: **заморожены только имена ключей
   и типы**, а сами границы — **runtime-данные каждого бэка** (CRM их не хардкодит,
   тесты их не ассертят).
7. Конфликт `if_updated_at` → **`409`**. Списки **не пагинируются**; ответ с **> 500**
   элементами CRM отвергает как contract mismatch (`502 backend_admin_unavailable`).
8. **`X-Admin-Actor`** (опц. заголовок, ≤255; CRM шлёт `crm:<user_uuid>`) — **заявление,
   а не аутентификация**: значение ничем не подтверждается и **непригодно** как
   основание отчёта «кто менял». Аутентификация одна — `X-Admin-Key`.

## Реализация в CRM (предписание)

- **Клиент бэков** (`infra/backend_admin_client.py`) — расширяется, а не дублируется:
  - **семантика 404 задаётся вызывающим явно, без значения по умолчанию** — три исхода
    `CONTRACT` / `USER` / `EXTENSION` ([ADR-072](../../adr/ADR-072-crm-admin-api-v11-economics.md) §4б).
    Отсутствие дефолта — гейт: каждый новый метод обязан решить вопрос сам, иначе
    копипаст воспроизведёт ложное «Пользователь не найден» на странице без пользователя;
  - **детекция префикса разводится с вызовом расширения**: префикс определяется
    **всегда по v1-пути `GET /products`**, расширенные вызовы идут только против уже
    определённого префикса. Иначе первый же вызов расширения при холодном кэше даёт
    «контракт не реализован» и префикс не кэшируется вовсе;
  - новые методы под расширенные пути (правка токенов продукта, чтение/правка тарифов,
    чтение capabilities) + приватный `PATCH`-путь;
  - маппинг **409** → `backend_admin_conflict`.
- **Общий резолвер источника** — путь расшифровки admin-ключа бэка **выносится из
  `services/backend_user_service.py` в общий модуль** и переиспользуется обоими
  сервисами: дублировать security-critical код во второй сервис нельзя. Рефакторинг
  идёт **вместе с тестами** — предписание безусловное и от текущего покрытия не
  зависит (сценарии —
  [06-testing-strategy.md](../../06-testing-strategy.md#backend-users--backend-economics-adr-069--adr-072);
  фактическое покрытие — только в [§Состояние](#состояние-замер-на-замороженном-дереве-2026-08-06)).
- **Сервис/роутер** `api/backend_economics.py` (`prefix="/backend-economics"`) +
  `services/backend_economics_service.py` + `schemas/backend_economics.py`. Отдельный
  роутер, а не расширение `backend_users.py`: другой RBAC-гейт, ресурсы не вложены в
  пользователя ([ADR-072](../../adr/ADR-072-crm-admin-api-v11-economics.md) §2).
- **Ответы бэка валидируются Pydantic-схемами** (как в v1): не по контракту → `502`.
- **`GET /backends`** — лёгкий список бэков с admin-ключом под **`backend-economics:view`**:
  селектор приложения **не должен зависеть от чужого права `backends:view`**. На
  `/backend-users` отсутствие этого права смягчено режимом «Все приложения»; здесь оно
  было бы фатальным (правка возможна только в конкретном бэке — режима «Все
  приложения» на этой странице **нет**).
- **capabilities возвращаются конвертом вместе со списками** (`{items, capabilities}`),
  отдельного CRM-эндпоинта нет: список и его write-аффорданс обязаны приходить одним
  снимком.
- **Аудит** — существующее событие `backend_admin_action` (`infra/audit.py`), поле
  пользователя-цели становится опциональным; новые действия **`product_tokens_updated`**
  и **`pricing_updated`**, в детали пишется **дельта** (`1000->1500`) из
  `previous_tokens`. Пишется **только после успеха бэка**; секреты в аудит и логи не
  попадают. **Деталь называет изменённое поле** ([ADR-072](../../adr/ADR-072-crm-admin-api-v11-economics.md) §10):
  `tokens=<prev>-><new>` — только если `tokens` был в теле запроса; **`avatar_tokens=<new>`** —
  если в теле был он (авторитетного прежнего значения у аватар-токенов **нет**, §8);
  при правке обеих величин — обе части в одной записи. Запись `tokens=1000->1000`
  при правке одних аватар-токенов — **дефект**: сообщает о правке, которой не было,
  и умалчивает о той, которая была.
- **Frontend:** `features/backend-economics/`, `pages/BackendEconomicsPage.tsx`, маршрут
  **`/backend-economics`**, пункт навигации **«Продукты и тарифы»**. Правка — **инлайн в
  ячейке** (`InlineEditField`, прецедент таблицы номеров СМС), не модалка: значение —
  один скаляр, `PATCH` идемпотентен. Инвалидация правки продукта задевает и кэш списка
  продуктов страницы «Юзеры бэков» (форма «Установить план» показывает тот же продукт).
- **История запросов** пользователя (страница «Юзеры бэков») получает колонки
  «Списано токенов» и «Себестоимость» + пометку возврата по `refunded`.

## RBAC

- Новый ключ каталога прав **`backend-economics`** с действиями **`view`** / **`edit`**
  ([ADR-021](../../adr/ADR-021-rbac-users-roles.md), каталог —
  [05-security.md](../../05-security.md#каталог-прав-канон-на-сервере)), в `CATALOG` —
  сразу после `backend-users`. **Миграции не требуется** (`roles.permissions` — `jsonb`,
  добавление аддитивно; супер-админ получает право через полный каталог, остальные роли
  fail-closed).
- **`backend-economics` — не алиас `backend-users:edit`**: то — операция над одним
  пользователем, это — глобальное изменение, влияющее на все будущие покупки и
  генерации. Роль с полным `backend-users:["view","edit"]` и **без** `backend-economics`
  получает **`403`** на **всех** путях `/api/backend-economics/*`.
- Чтение (`GET`) — `require("backend-economics","view")`; правка (`PATCH`) —
  `require("backend-economics","edit")` + аудит.
- **Замороженный контракт-тест каталога прав** правится в том же проходе — иначе CI
  красный при корректном изменении.

## Деградация (нормативно)

Состояния двух таблиц («Продукты» и «Тарифы списания») **независимы** — отказ одной не
гасит другую.

| Ситуация | Код CRM | Поведение UI |
| --- | --- | --- |
| Бэк реализует только v1 — **таблица «Тарифы списания»** (`404` на `GET /pricing`, пути нет вовсе) | `502 backend_admin_extension_not_supported` | **Информационный** блок «бэк не поддерживает расширение» — **не** красная ошибка и **не** «пользователь не найден»; кнопки повтора нет (повтор ничего не изменит) |
| Бэк реализует только v1 — **таблица «Продукты»** (`GET /products` — **v1-путь**, отвечает **`200`** без новых полей) | **кода нет — `200`** | Состояние выводится **из данных** ([ADR-072](../../adr/ADR-072-crm-admin-api-v11-economics.md) §1.1): `items` непуст и **ни один** элемент не несёт `tokens` ⇒ **ТОТ ЖЕ** информационный блок, что у тарифов (обе таблицы выглядят одинаково — причина одна). `items: []` сюда **не** относится (empty state) |
| Бэк отдаёт `tokens` **частично** (часть элементов без него) | **кода нет — `200`** | Таблица рендерится: элемент без `tokens` → ячейка **`—`** и **read-only** строка (карандаш не рендерится ни при каком праве — текущее значение неизвестно, править нечего); `grantable: null` → **`—`**, а не «Нет». Жёлтого блока нет |
| Элемент `/pricing` без обязательных полей (`tariff_id`/`kind`/`tokens`) | `502 backend_admin_unavailable` | Ошибка (contract mismatch): путь существует **только** в v1.1, его поля обязательны — **асимметрия с `products` намеренная** |
| `/capabilities` ответил **не 404**: таймаут, `5xx`, `401`/`403`, битый JSON | **кода нет — `200`** | **Список отдаётся**, `capabilities: null` ⇒ **все контролы правки скрыты** при любом праве (fail-closed) + **нейтральная подсказка держателю `edit`** («Правка недоступна: бэк не подтвердил поддержку изменения значений»; держателю только `view` не показывается). Провалить список в `502` из-за необязательного подзапроса **запрещено**; причина — в лог событием **`backend_admin_capabilities_unavailable`** (`backend_id`, `reason` ∈ `not_found\|timeout\|transport\|redirect\|rejected\|http_4xx\|http_5xx\|bad_json\|schema_mismatch` — перечень закрыт и проверяется по классам исхода, [ADR-072](../../adr/ADR-072-crm-admin-api-v11-economics.md) §7.1) |
| У бэка не задан Admin API Key | `409 backend_admin_key_not_set` | Подсказка «задайте Admin API Key в карточке бэка» |
| Значение изменил другой оператор (`if_updated_at`) | `409 backend_admin_conflict` | Тост «обновите страницу» + автоматический refetch |
| Неизвестный `product_id`/`tariff_id` | `400 backend_admin_bad_request` | Тост с текстом бэка (**не** «расширение не поддерживается») |
| `/capabilities` не реализован (`404`) | — | Таблицы читаются, **контролы правки не рендерятся ни при каком праве** (fail-closed, [ADR-072](../../adr/ADR-072-crm-admin-api-v11-economics.md) §7) |
| `limits` пуст / ключа нет / `capabilities: null` | — | Клиентская проверка **по отсутствующему ключу не выполняется** (полагаемся на `400` бэка); форма **остаётся работоспособной**. Проверки «число / целое / `≥ 0`» действуют всегда |
| Нет права `backend-economics:view` | `403 forbidden` | Заглушка «Недостаточно прав» |

## Ограничения

- **`backend_user_not_found` недостижим** с роутера `/api/backend-economics` — в нём нет
  ни одного пути, содержащего пользователя. Появление этого кода на странице «Продукты и
  тарифы» = дефект, а не состояние.
- **Режима «Все приложения» на странице нет** — правка возможна только в конкретном
  бэке; селектор приложения обязателен.
- **БД-миграций нет** — модуль не добавляет таблиц (§Принцип).
- **Правка применяется у бэка не мгновенно** (его собственный кэш каталога между
  процессами): величина задержки приходит в `effective_after_seconds` и **показывается
  оператору**. Окно рассинхрона делает дорогим не его длительность, а невидимость.
- **Отката правки нет** и подтверждающей модалки нет (решение владельца): видимость
  обеспечивается дельтой `previous_tokens → tokens` в тосте и в аудите. ⛔ **Дельта
  аватар-токенов из `previous_tokens` НЕ строится** — это другая величина; авторитетного
  прежнего значения у `avatar_tokens` в замороженном контракте нет, клиент берёт его из
  собственного снимка, а при отсутствии показывает результат без дельты
  ([ADR-072](../../adr/ADR-072-crm-admin-api-v11-economics.md) §8, [TD-080](../../100-known-tech-debt.md)).
- **Правка тарифа — не «отчётная цифра»**: тот же тариф у бэка обслуживает
  пользовательские пути расчёта стоимости генерации.
- **Кэш определённого префикса не инвалидируется при смене домена бэка** —
  [TD-078](../../100-known-tech-debt.md); примитив инлайн-правки без пропа ошибки и
  числового режима ⇒ валидация живёт в вызывающем коде — [TD-079](../../100-known-tech-debt.md).
- Реализация расширения **на стороне каждого бэка** — отдельная задача в его
  репозитории.
